# Правила работы с RAG-MD

- Сначала вносить изменения локально и выполнять соответствующие локальные тесты. Отправлять изменения на GitHub только после успешных проверок. О недоступных проверках сообщать до отправки.
- Никогда не добавлять в коммиты и не отправлять на GitHub содержимое `docs/`, `qdrant_storage/`, `processed/`, `backup/` и файл `.env`. Документы, векторная база, извлечённый текст и учётные данные являются частными рабочими данными.
- Сохранять исключения этих путей в `.gitignore` и `.dockerignore`. Не обходить их через `git add -f`, архивы, копирование данных в другие каталоги или добавление данных в тестовые фикстуры.
- Перед коммитом и отправкой проверять список подготовленных файлов; частные данные не должны присутствовать среди отслеживаемых файлов.
- Для тестов использовать искусственные данные и временные каталоги. Локальные скриншоты и результаты генерации из `output/` не публиковать.
